## 中控、HDMI 和桌面虚拟显示

| Android displayId | 归属与类型 | 系统显示尺寸 | 密度与刷新率 | 当次读数 |
| --- | --- | --- | --- | --- |
| 0 | 内置中控默认显示 | 1920 × 1200 px | 160 dpi，约 60 Hz | 旋转 0。在 WindowManager 显示覆盖信息中，应用区域为 1920 × 1080 px，实际显示尺寸仍为 1920 × 1200 px |
| 1 | HDMI，标记 `PRESENTATION` | 800 × 480 px | 142 dpi，约 60 Hz | Android 报告 HDMI 和外部触控类型。具体对应哪个车内屏幕、普通应用能否投放仍待验证 |
| 2、3 | ECARX 桌面创建的虚拟显示 | 1920 × 1200 px | 160 dpi，60 Hz | 当次由 `ecarx.launcher3` 创建 |
| 4 | ECARX 桌面创建的窄幅虚拟显示 | 630 × 1200 px | 160 dpi，60 Hz | 当次由 `ecarx.launcher3` 创建 |

- `wm size` 与 `wm density` 对默认中控只返回物理设置 1920 × 1200 和 160 dpi，没有报告用户覆盖值。硬件显示描述另报 xdpi / ydpi 320.842，这是驱动报告值。布局使用逻辑密度 160 dpi。
- Android 全局资源配置报告 `w1920dp-h1000dp-sw1200dp`、`land`、`car`、`night`、`mdpi`。1920 × 1200 px、1920 × 1080 px 与 1920 × 1000 dp 来自不同层，不能互换。桌面窄窗与其他实际应用窗口要从对应 Activity 的 `Configuration.screenWidthDp/screenHeightDp` 取值。虚拟 displayId 也按运行时枚举处理。[Android Configuration](https://developer.android.com/reference/android/content/res/Configuration) · [Android DisplayManager](https://developer.android.com/reference/android/hardware/display/DisplayManager)
- Apple Music 试装包的门槛为横屏且窗口至少 640 × 320 dp。实测全局配置满足这一门槛，630 px 的桌面窄幅视图值得在后续应用启动时验证。此次只查了设备，没有在 Apple Music 的 Activity 内测量。
- 原车地图样本对 001 8155 记录了仪表 1920 × 480 和 HUD 800 × 480。此次 Android 显示列表没有单独出现一个 1920 × 480 逻辑屏幕。不能仅凭 800 × 480 就把 HDMI ID 1 确认为 HUD。

## 普通 Android 应用可参考的能力

| 方向 | 车机声明或只读证据 | 应用接入与验收 |
| --- | --- | --- |
| 显示与输入 | 系统声明触控、多点触控及 `activities_on_secondary_displays`。DisplayManager 有两块物理输出和当次三个虚拟显示 | 使用 `Configuration`、`DisplayManager` 和 `MotionEvent`。是否可见或可启动到特定副屏以普通应用实际权限和 Launcher 行为为准 |
| 音频与媒体 | 系统声明麦克风和音频输出。音频策略列有扬声器、内置和后置麦克风、FM 输入、音频总线以及蓝牙 A2DP/SCO 等设备类型 | 使用 `AudioManager`、`MediaSession`、`AudioTrack/AudioRecord`。已连接输出、车机音区和音频焦点需运行应用验证 |
| 编解码与 DRM | 厂商配置声明 AAC、MP3、FLAC、Opus、Vorbis，以及 AVC、HEVC、MPEG-2、MPEG-4、VP8/VP9 等。DRM HAL 声明 1.0，注册了 `media.drm` | 用 `MediaCodecList` 核对编解码方向、分辨率与 profile，用具体内容验证 DRM 和播放。配置没有给出 App 最终获得的能力或 Widevine 等级 |
| 定位与运动 | 声明 GPS 与网络定位。SensorService 枚举了加速度计、陀螺仪、重力和游戏旋转向量 | 使用 `LocationManager` 和 `SensorManager`，按需求处理授权与传感器缺失 |
| 网络与外设 | 声明 Wi-Fi、Wi-Fi Direct、Wi-Fi RTT、以太网、Bluetooth Classic/BLE、USB Host 与 Accessory | 使用 `ConnectivityManager`、Bluetooth、USB 标准 API，按应用测实际连接 |
| 摄像头与广播 | 系统声明摄像头、前摄、自动对焦与广播收音机 | 摄像头使用 Camera2 枚举实际可用设备并处理权限。广播接口以公开 SDK 和权限为准 |
| 安装与桌面 | ECARX Launcher 包和版本已确认，Apple Music 包未找到 | 保留标准 `MAIN` / `LAUNCHER`，设备安装与桌面打开分别验收。Apple Music 使用现有三个分包同批安装 |

上述接口目录来自实车只读查询与静态分析，仅供应用兼容开发参考；所有试装流程均仅限于普通用户空间应用安装与兼容，不修改车机系统文件。

## 取证和复查

- 通过 USB ADB 的 shell UID 2000 只读读取。平台与资源配置来自选定 `getprop`、`wm size`、`wm density`、`am get-config`、`dumpsys display`、CPU 拓扑、`/proc/meminfo` 与 `df -k /data`。
- Android 能力来自 `pm list features`、`pm list libraries`、`service list`、厂商媒体 XML 与 HAL manifest。音频、显示、WebView 和传感器只抽取与应用开发相关的字段。
- 包状态用 `am get-current-user` 得到数值 ID 后定向查询，另与 `dumpsys package com.apple.android.music` 交叉核对。车机上 `pm list packages --user current` 对已存在的桌面包也返回空，因此用数字用户 ID。
